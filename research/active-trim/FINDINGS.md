# Сжатие памяти активных приложений: без VM, без драйвера

## Вопрос

Можно ли сжимать память приложения, которым сейчас пользуются (активный браузер, мессенджер), только средствами
Windows, без своей виртуальной машины и без драйвера, так, чтобы приложение этого не заметило?

## Ответ (по замерам на настоящей Windows)

**Да. Нужно вытеснять не весь рабочий набор, а только холодные страницы.** Сжимает их сама Windows
(Memory Compression), а при обращении прозрачно возвращает: для программы это обычный soft fault.
Вся новизна в том, *какие* страницы отдавать. Это решает user-mode агент с точностью до страницы 4 КиБ.

| | EmptyWorkingSet всего процесса (как сейчас) | постраничный агент (v3) |
|---|---|---|
| Синтетика 1 ГиБ, из них 96 МиБ горячих + 64 МиБ тёплых, 60 кадров/с | в памяти 34–55 МиБ: выброшены и **горячие** страницы | в памяти 160 МиБ: ровно горячие и тёплые, холодных 0 |
| Время кадра p99 / максимум | 37–42 мс / 106–141 мс, 21–29 кадров дольше 16 мс за 20 с | 0,7–1,2 мс / 1,8–19,8 мс (как без агента) |
| Возвраты страниц | 16 400/с | 31/с |
| Edge headless, 37–39 процессов, ~1 ГиБ приватной памяти | — | в памяти 933 → 181–206 МиБ (**−78…81 %**), 60 кадров/с, 0 рывков > 50 мс |
| CPU агента | — | 1,5–2,2 % одного ядра (v2: 7 %) |

Прогоны: GitHub Actions, Windows Server 2022 (20348) и 2025 (26100), 2 vCPU, 8 ГиБ.
Сырые логи: `results/` (v3), `results-v2/`, `results-v1/`.

**Чего не доказано.** На серверных раннерах Memory Compression выключен. Вытесненные страницы там уходили в
файл подкачки и списки standby. «Доступно ОЗУ» при этом росло на +250…920 МиБ. Сколько именно сэкономит сжатие на
Windows 10/11 и какова цена возврата из сжатого хранилища (ожидаем ~3–10 мкс против ~0,7–1 мкс здесь),
покажет только тест на клиентской Windows. Для этого есть `ТЕСТ-АКТИВНОЕ-СЖАТИЕ.cmd`.

## Механизм: три штатных вызова Windows

1. **Вытеснить конкретные страницы чужого процесса.**
   `NtSetInformationVirtualMemory(h, VmRemoveFromWorkingSetInformation, …)` выбрасывает из рабочего набора ровно
   указанный диапазон. Запасной вариант — `NtUnlockVirtualMemory(h, …)`: он возвращает `STATUS_NOT_LOCKED`, но
   страницы всё равно вытесняет. Оба проверены на чужом процессе: 16 из 16 страниц вытеснены, вызов занимает 10–70 мкс.
   Нужны права `PROCESS_VM_OPERATION`.
2. **Узнать, что страница понадобилась.** Если вытесненная страница снова `Valid` в `QueryWorkingSetEx`, процесс её
   тронул. Нужны права `PROCESS_QUERY_INFORMATION`. Это сигнал доступа без драйвера и без чтения чужой памяти.
   Working Set Watch (`GetWsChangesEx`) проверен и отброшен: он терял ~70 % записей.
3. **Сжать.** Это делает Windows: страница уходит в modified list, а затем в хранилище Memory Compression.

Своего кодека нет, поэтому степень сжатия такая же, как у Windows (XPRESS). Выигрыш даёт **охват**: под сжатие
уходит 80 % памяти работающего приложения, а не только память «уснувших» процессов.

## Политика (`probe.c`, v3)

- **Неизвестные страницы** пробуем срезами раз в 250 мс. Бюджет среза — `100 / доля_возвратов`
  (EWMA, 128…65 536 страниц). На кадр приходится не больше ~100 возвратов, а не «вся память разом».
  Это контроллер по цене возвратов, как в TMO/PSI.
- **Вернувшаяся страница** становится горячей. Следующая проба через 8 с, потом пауза растёт ×4 до 5 мин.
  Горячих пробуем не больше 4–8 за срез.
- **Недавно вытесненные** (< 3 с) проверяем каждые 250 мс. Остальные проверяет полный опрос раз в 2–4 с.
  Поэтому CPU не растёт с объёмом сжатого.
- Берём только приватную RW-память: без guard/nocache/write-combine, без locked/large/shared страниц.

## Что осталось и риски

- **Обучение.** Первые ~40 с синтетика давала p99 15–22 мс: горячие страницы разбросаны случайно, это худший случай.
  Варианты: учиться в фоне, пока окно неактивно, или использовать соседство страниц (регион 64 КиБ) как подсказку.
- **Античиты и защищённые процессы.** Используем существующий список `ProcRoles` и не трогаем такие процессы.
  Процессы PPL открыть и нельзя.
- **Звук, GPU, реальное время.** Их тоже не трогаем (уже есть в `ProcRoles`).
- **Права.** Для своих процессов администратор не нужен, для чужих пользователей нужен.
