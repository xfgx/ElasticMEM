# em-cas, em-pagestat, em-pager, em-whp-proxy

Новая ось: меняем не кодек, а единицу хранения.

- **em-cas** — content-addressed хранилище страниц 4 КиБ.
  - Zero: нулевая страница, payload не хранится.
  - Full / Raw: сжатая (LZ4 или XPRESS) или несжимаемая страница. Одинаковые страницы делят одну запись:
    индекс по первым 64 битам SHA-256, побайтовая сверка при совпадении, refcount.
  - Delta: ссылка на цельную базу плюс сжатый XOR (page ^ base). База ищется по скетчу из 3 super-feature
    (min-hash по ненулевым словам). Глубина цепочки всегда 1; дельта принимается, только если она меньше
    половины обычного сжатия.
  - Временна́я дельта: вызывающий передаёт подсказку — прошлую сохранённую версию той же страницы.
  - Безопасное восстановление: generation в ссылке и CRC32 исходной страницы в записи. Ошибка возвращается
    как ошибка, молча неверных байтов не бывает.
  - Реальное освобождение памяти: payload'ы лежат в сегментах ОС по 64 КиБ (VirtualAlloc / mmap), 64 размерных
    класса с шагом 64 байта. Пустой сегмент сразу возвращается ОС. Компактор переносит payload'ы (владельцы
    ссылаются на id, а не на адрес) и освобождает полупустые сегменты.
  - В stats().total_bytes() входят сегменты и оценка индексов и таблицы записей, то есть честная стоимость
    хранилища.
- **elastic-arena + em-cas**: Arena::new_cas, в arena-bench — EM_STORE=cas, EM_DUP_PCT, EM_NEAR_PCT, EM_GHOST,
  EM_MUTATE. Плюс экономия по счётчикам ОС (OSMEM). Повреждённое хранилище работает fail-closed: VEH отдаёт
  исключение дальше.
- **em-pagestat** — Gate 0. На настоящей памяти сравнивает:
  - нулевые страницы и точные дубликаты (внутри процесса и между процессами);
  - em-cas целиком (с проверкой восстановления без потерь);
  - временну́ю дельту между снимками;
  - обычное постраничное сжатие LZ4 и XPRESS.

  Источники: живые процессы (на Windows читаются только резидентные страницы, по QueryWorkingSetEx), полный
  минидамп, сырой образ, синтетика. Выводит только агрегаты.
- **em-pager** — пейджер памяти гостя для QEMU/WHPX поверх em-cas. Переносимое ядро тестируется на модели
  гипервизора. Привязка к Windows (win.rs): VEH, остановка потоков на время восстановления, компактор, журнал.
- **em-whp-proxy** — WinHvPlatform.dll для немодифицированного QEMU (см. vm/qemu-whpx/README.md).

Тесты: `cargo test --release -p em-cas -p elastic-arena -p em-pager`. Результаты CI на Windows лежат в results/
(workflow cas-memory).

elastic-arena держит память в разделе ОС с двумя видами: байты страницы пишутся через второй вид, пока у вида
приложения ещё нет доступа. Поэтому другой поток не может увидеть страницу посреди восстановления. Подробности
и замеры — в FINDINGS.md, «Обновление 5».
