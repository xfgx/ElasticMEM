## Выводы
1. Цикл «вытеснение → fault → restore → повтор инструкции» нативно работает на WHP (один vCPU, синтетический гость). Хранилище здесь user-mode; путь через SYS не проверен.
2. Windows уже вытесняет память, отображённую в WHP-партицию: страницы не закреплены, гипервизор и ОС прозрачно возвращают их без выходов в VMM. Значит, собственный пейджер в WHP-VMM дублирует штатный менеджер памяти. Польза возможна, только если он сжимает лучше или выбирает страницы точнее, чем Windows + Memory Compression, а сейчас используется тот же XPRESS.
3. `physical_ram_saved_bytes = null`: на 64 страницах экономию не измерить, и сравнения с ОС в этом прогоне не было.

## Не проверено
Windows 11, HVCI, Driver Verifier, SYS-путь, multi-vCPU, загрузка Windows-гостя, Gate 0.
