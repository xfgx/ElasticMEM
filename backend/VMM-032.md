# ElasticMem 0.32 — диагностика WHP, путь без драйвера, host-trim и Gate 0

**Критерий готовности пользователя НЕ выполнен.** Windows-гость не загружается, Edge/Chrome/Telegram в своём VMM не запускаются, `physical_ram_saved_bytes = null`. 0.32 — это исправления и инструменты, которые позволяют за один заход на Windows получить ответы на три вопроса, без которых дальше идти нельзя:

1. Работает ли WHP-путь 0.31 нативно (fault → restore → повтор инструкции)?
2. Может ли сама Windows уже вытеснять память WHP-гостя (тогда свой пейджер дублирует ОС)?
3. Есть ли вообще что экономить: сколько RAM стоит гостевая Windows по сравнению с нативным запуском тех же приложений (Gate 0)?

## Что исправлено по сравнению с 0.31

| Проблема 0.31 | Исправление 0.32 |
|---|---|
| Runner скрывал причину отказа WHP: в JSON был только `PlatformNotSupportedException` | В JSON есть `failed_stage` (`whp_probe`, `sys_open`, `partition_create`, `vp_run`, `pager_restore`, `guest_verify`, `teardown`, …), `whp_status` (`whp_dll_missing_enable_HypervisorPlatform_feature`, `hypervisor_not_present`, `capability_failed`, …), `hresult`, `win32_error`, сборка ОС, признак Windows 11, elevated. Тексты исключений, регистры и память по-прежнему не выводятся. |
| WHP проверялся раньше SYS, поэтому один прогон показывал только одно препятствие | `--probe` проверяет WHP и SYS независимо и сразу говорит, какие пути возможны |
| `win32_error: 2` подавалось как «нужен новый SYS» | Отдельные статусы: `driver_not_installed_or_not_started` (2/3), `access_denied_requires_elevated_admin` (5), `driver_protocol_unsupported_old_sys` |
| Проверить WHP-путь без подписанного драйвера было нельзя | `--store user`: то же хранилище со сжатием XPRESS (compressed-only, generation, CRC, квота, учёт payload+24 байта), но в user mode через `ntdll!RtlCompressBuffer`. Драйвер, подпись, test-signing и отключение Secure Boot не нужны. |
| Метрики были только по процессу: уход страниц в paged pool драйвера выглядел как «экономия» | В каждом снимке есть `SystemCommitBytes`, `KernelPagedPoolBytes`, `KernelNonpagedPoolBytes`, `SystemCacheBytes`. SYS-хранилище лежит в paged pool, вне RSS процесса. Сравнивать нужно системные числа. |
| Ошибка при teardown в `finally` могла скрыть исходную ошибку | Ошибки teardown собираются отдельно; при успешном прогоне они дают `failed_stage=teardown` |
| Выход `Canceled` (0x2001) после watchdog обрабатывался как «неизвестный выход» | Распознаётся явно как timeout |
| Нет ответа, вытесняет ли Windows память WHP сама | Новый режим `host-trim` (ниже) |
| Нет методики A/B «нативно против VM» | `backend/windows/Gate0-Measure.ps1` и `Gate0-Compare.ps1` |
| Нет нативной сборки и проверки ABI | `.github/workflows/windows-native.yml`: тесты на Windows, нативный self-test XPRESS, проверка ABI против реального Windows SDK, попытка WDK-сборки, `--probe` и WHP-прогоны с сохранением результатов |

## Порядок проверки (disposable Windows x64, лучше Windows 11)

Все команды только читают и измеряют: ничего не устанавливают, не включают и не меняют BCD или настройки безопасности.

```powershell
.\vmm-runner\ElasticMem.VmmRunner.exe --probe                      > 01-probe.json
.\vmm-runner\ElasticMem.VmmRunner.exe --selftest-user-store        > 02-user-store.json
.\vmm-runner\ElasticMem.VmmRunner.exe --research-disposable host-trim 3                > 03-host-trim.json
.\vmm-runner\ElasticMem.VmmRunner.exe --research-disposable synthetic 32 --store user  > 04-whp-user.json
.\vmm-runner\ElasticMem.VmmRunner.exe --research-disposable inject-store-loss 1 --store user > 05-whp-user-loss.json
# только если 01-probe.json показывает sys.status = ok (новый подписанный SYS в лаборатории):
.\vmm-runner\ElasticMem.VmmRunner.exe --research-disposable synthetic 32 --store sys   > 06-whp-sys.json
```

- **01** сообщает, доступен ли WHP и почему нет. Если `whp.Status = whp_dll_missing_enable_HypervisorPlatform_feature`, компонент «Платформа низкоуровневой оболочки Windows» не включён. Включать его или нет, решаете вы; программа ничего не включает. Внутри VM нужна nested virtualization.
- **02** выполняется без WHP и без драйвера: нативный XPRESS round-trip для нулевых, константных, текстовых и случайных страниц. Случайные страницы должны отклоняться как невыгодные.
- **03** — host-trim. Гость читает и пишет 16 страниц. Затем вызывается `EmptyWorkingSet` для **собственного** процесса, `QueryWorkingSetEx` показывает, сколько страниц осталось резидентными, после чего гость снова читает все страницы с проверкой содержимого. Если `verdict = host_can_trim_whp_mapped_memory`, Windows уже умеет вытеснять (и сжимать) память WHP-гостя без нашего пейджера.
- **04/05** — исходный тест 0.31 (вытеснение → fault → restore → повтор инструкции, инъекция отказа GET), но с user-mode хранилищем.

UI: тип 1 → новые кнопки «WHP + user-store (без SYS)» и «host-trim проверка». Отчёты пишутся в `%LOCALAPPDATA%\ElasticMem\whp-sys-reports`.

## Gate 0 — до любых работ по VMM для Windows

Цель — измерить, во сколько RAM хоста обходятся те же приложения, запущенные нативно и внутри VM. Используется существующая VM (Windows Sandbox или Hyper-V). Свой VMM для этого не нужен.

1. Один и тот же сценарий в обеих фазах: одинаковые профили, одни и те же вкладки и URL, Telegram с тем же аккаунтом, одинаковое время простоя.
2. Фаза A (native): приложения на хосте.
   `.\backend\windows\Gate0-Measure.ps1 -Phase native -Label a1 -DurationMinutes 15`
3. Фаза B (vm): приложения на хосте закрыты, те же приложения внутри VM.
   `.\backend\windows\Gate0-Measure.ps1 -Phase vm -Label b1 -DurationMinutes 15`
4. Повторить A и B ещё хотя бы по разу, чередуя их и соблюдая одинаковое состояние перед каждым прогоном.
5. `.\backend\windows\Gate0-Compare.ps1 -Native a1.json,a2.json -Vm b1.json,b2.json -Out gate0.json`

Основная метрика — `in_use = total - available` по всему хосту: она включает хранилище Memory Compression, kernel pool и vmmem. Число `physical_ram_saved_bytes` появляется **только** если VM-путь потребляет меньше, разница больше разброса и предупреждений нет. Один прогон на фазу никогда не даёт этого числа.

**Решение по итогам.** Если `verdict = vm_path_costs_more_ram`, свой пейджер должен вернуть больше, чем показывает разница, и сверх того, что Windows уже сжимает нативно, причём тем же кодеком XPRESS. Пока не найден механизм, который заметно лучше XPRESS и Memory Compression для гостевых страниц, шаги 2–6 (загрузка Windows, multi-vCPU, приложения в госте) не окупаются.

## Подпись драйвера: решение за вами

При включённом Secure Boot тестовая подпись не загружается: test-signing требует выключенного Secure Boot, и проверка 0.24 так и проходила. Если ограничения «не отключать Secure Boot/HVCI» действуют и в disposable VM, остаётся attestation signing через Microsoft Partner Center (нужен EV-сертификат) и проверка совместимости с HVCI. Путь `--store user` эту зависимость снимает для всех проверок, кроме самого SYS.
