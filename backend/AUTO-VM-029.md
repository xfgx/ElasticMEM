# ElasticMem 0.29 — автоматическое создание VM из приложения

## Что делает одна кнопка

**Backend VM → Создать Windows VM автоматически…** открывает короткий мастер. Один раз выберите доверенный образ и сеть, затем нажмите **Создать и запустить VM автоматически**. PowerShell-команды вручную для этого сценария не нужны.

Программа проверяет Hyper-V/VMMS, бюджет RAM/CPU/диска, считает SHA256, делает независимую приватную копию образа, создаёт Hyper-V Generation2 VM, включает Secure Boot MicrosoftWindows и vTPM с локальным key protector, назначает CPU/Dynamic Memory и выбранный существующий switch, проверяет настройки, запускает VM и привязывает полученный GUID. Затем открывает VMConnect. Существующие VM, их диски и сети не перезаписываются.

**Это автосоздание Hyper-V VM, а НЕ законченная установка всей системы и НЕ custom SYS-pager.** Windows внутри гостя ещё должна загрузиться/пройти свои проверки. После успешного старта Hyper-V результат называется `created_running_guest_unverified`, не «всё готово».

## Два варианта образа

- **Подготовленный VHDX с установленной Windows** — для автоматического запуска готовой ОС. Диск должен быть standalone Dynamic/Fixed, не attached и без ParentPath/differencing chain; Windows должна поддерживать UEFI/Gen2/Secure Boot. Используйте свой разрешённый standalone/generalized образ, не доменный рабочий сервер, не диск работающей машины и не BitLocker-диск, привязанный к прежнему TPM. Образ не обязан содержать приложения — но их установка тогда остаётся отдельной задачей.
- **ISO Windows** — программа создаст новый динамический VHDX и загрузит установщик с DVD. Установка ОС, выбор редакции, лицензирование и создание учётной записи **не автоматизированы** этим мастером. Если нужен запуск готовой ОС без установщика, выбирайте VHDX.

В поставку не включён Windows-образ. Программа не скачивает неофициальные ISO, не принимает лицензионные условия от вашего имени, не подменяет активацию и не обходит OOBE. Источник Windows и разрешение на его использование предоставляете вы. SHA256 здесь защищает от изменения выбранного файла; это не проверка издателя/чистоты образа.

## Требования хоста

- Windows Pro/Enterprise/Server с уже установленным Hyper-V и работающей службой VMMS. Если хост — VM, владелец должен разрешить nested virtualization. Windows Home/отсутствующий Hyper-V не превращаются автоматически в поддерживаемый хост.
- Запуск ElasticMem **от администратора** вручную. Никакого скрытого UAC или автоматического повышения прав.
- Не менее `startup RAM +1GiB` свободной физической RAM на этапе проверки. Это guard, не гарантия последующего запаса.
- На диске ProgramData: свободное место под полную виртуальную ёмкость VHDX +4GiB; для ISO также под сам ISO. Используется локальный NTFS/ReFS. После проверки другие программы могут занять место — резервирование полной ёмкости не выполняется.
- Разрешённое выполнение просмотренных PowerShell5.1-скриптов. Политики Bypass/Unrestricted, host Secure Boot/HVCI/Defender не меняются. При блокировке обратитесь к администратору, не отключайте защиту.

## Порядок действий

1. Распакуйте новую версию целиком в отдельную папку; проверьте SHA256. Закройте старый агент.
2. Запустите `ElasticMem.exe` от администратора, откройте **Backend VM**. Либо запустите `ElasticMem.exe --backend-ui`.
3. Установите желаемые min/startup/max RAM в панели. Нажмите **Создать Windows VM автоматически…**.
4. Выберите VHDX или ISO. Укажите новое имя VM, vCPU и существующий switch. Если есть стандартный `Default Switch`, мастер предлагает его; иначе по умолчанию **Без сети**. Новый external switch/NAT/правила firewall на хосте не создаются.
5. Подтвердите доверие образу/сети и нажмите кнопку создания. Прочитайте отдельное предупреждение для ISO. Дождитесь завершения: SHA256 и полная копия большого диска могут занять длительное время.
6. После создания откроется VMConnect. Проверьте загрузку гостя; для ISO завершите Windows Setup самостоятельно. При проблеме VMConnect факт создания/запуска VM не отменяется.
7. Для последующего управления гостем укажите его настоящий RDP hostname/IP вместо `unconfigured.invalid`, сохраните/привяжите профиль, затем сохраните **учётную запись нового гостя**. Мастер не знает его пароль, не копирует host-пароли и не делает автоматический вход.

С версии0.29 guest credential DPAPI scoped по **VM GUID**. Старый `guest-credential.clixml` предыдущих версий не импортируется автоматически: сохраните credential заново через кнопку. Старый файл можно удалить вручную после проверки. Создание новой VM не отправляет ей credential предыдущей VM.

## Что ещё НЕ настраивается автоматически

- Domain/RDS deployment, collection, RDS/Windows лицензии, сертификаты и пользовательские разрешения для RemoteApp.
- Edge/Chrome/Telegram и перенос их профилей/паролей/чатов.
- Новый подписанный SYS, собственный Windows-bootable VMM, vCPU/DMA barrier и сжатие памяти гостя через наш драйвер.

Окна RemoteApp не появятся только от создания VM: требуется поддерживаемая настроенная RDS-среда. Обычный рабочий стол хоста сохраняется; VMConnect — отдельное окно. SYS-кнопка0.28 по-прежнему тестирует только собственные синтетические страницы. Гостевой Windows Compression/Hyper-V DM — отдельный путь, не доказательство SYS-paging и не доказанная экономия физической RAM.

## Хранение, сбои и удаление

Копия диска/ISO, VM config/vTPM и `creation.json` находятся в `%ProgramData%\ElasticMemBackendVMs\<CreationId>`. Исходник открывается read-only с запретом совместной записи; SHA256 проверяется ещё раз в worker и после копирования. Journal хранит stage/VM GUID; исходная память/пароли туда не попадают. Key protector относится к самой VM, а не к публичному ZIP логов.

При ошибке/timeout ресурсы сохраняются для проверки. Программа **не делает force shutdown, не удаляет диски и не пробует бесконечно создавать VM заново**. Если worker не вернул подтверждение, результат неизвестен: проверьте Hyper-V Manager и journal перед повтором. Если одинаковое имя появилось извне во время создания, автоматическая привязка отвергается.

Для лабораторного удаления закройте guest apps, штатно выключите именно VM с указанным GUID, удалите её через Hyper-V Manager, убедитесь, что её диски не attached/не используются, и только затем удаляйте соответствующую GUID-папку. Не удаляйте весь общий каталог и не удаляйте исходный образ.

Backend ZIP логов содержит этапы создания, SHA256 образа, имена/IDs switch/VM и путь созданной папки. Это metadata, которое следует просмотреть перед отправкой. ZIP не включает ISO/VHDX, guest credentials, VM key protector или guest memory.

## Проверки готовности

Новая Windows-сборка компилируется; portable contract tests проверяют ввод, привязку результата, отсутствие ложной guest-readiness и scope credential. PowerShell parser проверяет синтаксис. **Нативное создание VM, настройка vTPM/SecureBoot, загрузка Windows и UI на Hyper-V здесь не выполнены.** Это исследовательский preview, не production-релиз.
