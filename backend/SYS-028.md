# ElasticMem 0.28 — первый этап «сжатие через SYS»

## Что изменено в коде

Это начало реализации, не законченный Windows-VM backend. В этой ревизии действительно изменены исходники `driver/core`, KMDF SYS и C#-клиента, а не только Hyper-V-панель.

1. `PUT_COMPRESSED` выполняет XPRESS **в SYS**. Только сжатый payload +24-byte node меньше4096 принимается; RAW fallback здесь запрещён. Невыгодная страница, quota/OOM или старая версия SYS оставляют исходный буфер у владельца.
2. Успех возвращает32-byte receipt: версия, ключ, непереиспользуемое поколение, payload, размер node и CRC32. Старое содержимое при отказе не заменяется. Reset не обнуляет поколение; переполнение отвергается.
3. `GET_VERSIONED`/`DELETE_VERSIONED` проверяют поколение под тем же lock, что запись. Устаревшая ссылка не может прочитать/удалить новую страницу. Изоляция по open handle сохраняется. Legacy PUT тоже меняет поколение.
4. SYS/WHP adapter использует только эти новые операции. VMM page-provider делает save → receipt validation → GPA unmap → backing decommit; затем GET поколения → SHA256 verification → commit/write/map → delete поколения. При неудаче восстановления гость должен оставаться остановленным.
5. GPA exit-router восстанавливает только принадлежащие provider сохранённые страницы. Неизвестные/MMIO/resident GPA не перехватываются.
6. В приложении добавлена кнопка **Backend VM → SYS · сжатие → освобождение → восстановление (свой буфер)**. Отдельный клиент имеет команду `pager-smoke`.

## Чего пока нет

Нет VMM, загружающего Windows с firmware/devices, реальной общей vCPU/DMA-паузы, подключения WHP run-loop к exit-router, автоматического выбора холодных страниц, защищённого shutdown/OOM recovery и store масштабирования до RAM полноценной VM. Store остаётся bounded:4096 страниц/session,16MiB/session quota,64MiB/global. Нельзя масштабировать этот код увеличением констант без redesign.

Нет миграции существующих host PID и нет сжатия Edge/Chrome/Telegram этой кнопкой. В Hyper-V панели по-прежнему отдельный Windows Compression/DM management-путь, **не наш SYS**. Его метрики не подтверждают драйверный pager.

## Как проверить на Windows

**Новый SYS здесь не собран и не запускался.** Новый app/client собран cross-target для Windows x64, а не выполнен на Windows. Прошлые `driver/verification/*` относятся к предыдущему драйверу и не квалифицируют эту ревизию.

1. Используйте одноразовую Windows x64 VM и checkpoint. Не production-хост с рабочими данными. Подготовьте разрешённую вашей политикой цепочку driver-signing; Secure Boot/HVCI/Verifier не отключать ради запуска.
2. Для сборки установите VS2022 Desktop C++, WDK/SDK10.0.26100 и .NET8 SDK. В Developer PowerShell из корня исходников:
   ```powershell
   .\driver\scripts\Build-Windows.ps1 -Configuration Release
   ```
   Это штатный MSBuild/WDK путь. LLD/cross-relink не используйте: старые такие варианты уже давали ошибки/BSOD.
3. Подпишите новый `driver\out\Release\ElasticMemStore.sys` своим утверждённым способом, проверьте доверие и SHA256, затем используйте просмотренный `Install-SignedDriver.ps1` по его параметрам. Удалите/остановите предыдущую лабораторную версию штатно, закрыв все клиенты; не заменяйте работающий SYS.
4. Запустите от администратора:
   ```powershell
   .\driver\out\client\ElasticMem.DriverClient.exe info driver-info.json
   .\driver\out\client\ElasticMem.DriverClient.exe pager-smoke pager-smoke.json
   .\driver\out\client\ElasticMem.DriverClient.exe smoke legacy-smoke.json
   ```
   Либо используйте SYS-кнопку в ElasticMem0.28. VM-профиль для собственной SYS-проверки не нужен.
5. На старом SYS новая операция завершится ошибкой до decommit. Не заменяйте её legacy PUT/RAW: это нарушит контракт экономии.

## Что именно делает pager-smoke

64 синтетические4KiB страницы в принадлежащем клиенту native VirtualAlloc регионе. Для каждой: SYS compressed PUT, проверка receipt, очистка managed scratch, VirtualFree MEM_DECOMMIT, проверка MEM_RESERVE через VirtualQuery. Затем versioned GET, полная проверка байтов, native commit/write/byte verification и versioned DELETE. При закрытии handles SYS освобождает session store.

Лог не содержит содержимое страниц, dump/пароли/guest memory. GUI сохраняет result+manifest в `%LOCALAPPDATA%\ElasticMem\sys-pager-reports`; для отдельного теста есть самостоятельный JSON. Backend VM ZIP-кнопка относится к Hyper-V журналу и не экспортирует этот новый SYS-отчёт. Отправляйте только просмотренные result/manifest, не диски VM и не дампы.

`released_owned_backing_commit_bytes` — подтверждённое decommit собственных буферов fixture. `retained_driver_session_allocation_bytes` включает session table и nodes, но не доказывает уникальную физическую RAM: allocator rounding, workspace, temporary buffers, managed GC и OS overhead не полностью учтены. `physical_ram_saved_bytes` остаётся null. `passed_owned_fixture_only` нельзя выдавать за успешный Windows guest pager.

## Проверки этой ревизии

Portable C core под ASan/UBSan: generation freshness, conditional delete/read, failure preservation, compress-only/raw rejection, overhead rejection, quotas, reset и counter exhaustion; codec здесь test-double, НЕ native XPRESS. Portable VMM model tests: ordering, stale generation, corrupted content, failed-paused rollback, owned GPA routing. Windows-target app/client build: compilation only.

Нужны отдельные Windows проверки SYS/KMDF/XPRESS, HVCI, Driver Verifier, crash/OOM/concurrency и долгий stress. Полноценный VMM — следующий этап, не скрытый уже готовый переключатель.
