# Путь C: аппаратная поддержка — прототип блока сжатия для контроллера памяти

## Что здесь сделано и проверено
| Файл | Что это |
|---|---|
| `bdi_model.py` | Эталонная модель сжатия кеш-линии 64 Б «база + смещения» (BΔI, с неявной нулевой базой): Zeros, Repeat, B8D1/B8D2/B8D4, B4D1/B4D2, B2D1, Raw. Плюс **выборочное чтение слова** без восстановления линии. |
| `bdi_rtl.py` | RTL на PyRTL: однотактный компрессор (все форматы проверяются параллельно), полный декомпрессор, блок выборочного чтения 64-битного слова, обёртка с регистрами. Симуляция сверяется с эталоном бит в бит. |
| `verilog/*.v` | Сгенерированный синтезируемый Verilog. |
| `synth.sh` | Синтез Yosys → Lattice ECP5, размещение/трассировка nextpnr → площадь и Fmax. |
| `dump_memory.py`, `analyze_real.py` | Снимок реальной памяти процесса и оценка: сжатие линий, трафик DRAM, ёмкость в LCP-раскладке. |

### Результаты (этот прототип)
- RTL ↔ эталон: 4000 линий (половина — из реальной памяти процесса), **0 расхождений**; выборочное чтение — 0 ошибок.
- ECP5-85F (без конвейера): компрессор ≈ 6,2 тыс. LUT4, выборочное чтение ≈ 4,6 тыс., полный декомпрессор ≈ 4,1 тыс.;
  обёртка «компрессор + чтение слова» ≈ 10,7 тыс. LUT4 (~13% кристалла), **52 МГц** → ≈ 3,3 ГБ/с на линию за такт.
  Конвейеризация (2–3 стадии) — очевидный следующий шаг для 100+ МГц.
- Реальная память процесса Python+pandas: BΔI сжимает линии до ≈ 82%, LCP-раскладка даёт ≈ +8% ёмкости,
  а Deflate по страницам 4 КБ — до ≈ 16%. **Аппаратно-дружественное сжатие быстрое и с произвольным доступом, но заметно слабее.**
  На числовых массивах (как в ElasticArray64) выигрыш многократно больше.

## Как довести до настоящего железа
1. **Своя система-на-кристалле на FPGA (реально сделать одному).** Плата ECP5 с DRAM (например, ULX3S, OrangeCrab, ECPIX-5)
   + LiteX: процессор VexRiscv с Linux + контроллер LiteDRAM. Блок ставится между кешем L2 и LiteDRAM:
   запись линии → компрессор → упаковка в LCP-страницу; чтение → таблица метаданных → выборочное чтение/распаковка.
   Программы на этом процессоре работают с обычной памятью — **сжатие прозрачно, как и задумано в пути C**.
2. **Карта памяти CXL на FPGA** (Type-3 memory expander) — тот же блок за интерфейсом CXL.mem. Нужна серверная платформа
   с поддержкой CXL; на обычном домашнем ПК с Windows 11 так не сделать.
3. **Уже есть в обычном ПК:** векторные инструкции AVX2/AVX-512 — их использует ElasticArray64 для декодирования
   «база + 16-битные смещения» прямо при проходе по данным.

## Запуск
```
pip install pyrtl yowasp-yosys yowasp-nextpnr-ecp5
python3 bdi_rtl.py 4000 [снимок_памяти.bin]   # проверка + Verilog
./synth.sh                                       # площадь и частота
python3 dump_memory.py mem.bin && python3 analyze_real.py mem.bin
```
