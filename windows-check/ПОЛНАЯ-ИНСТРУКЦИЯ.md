# ElasticMem 0.25.0 — полная установка и проверка Edge / Chrome / Telegram

## 0. Что именно проверяется

Два независимых режима:

1. **Программа без драйвера:** читает ограниченную копию resident/private/exclusive страниц выбранных приложений с вашим явным согласием; сравнивает XPRESS, XPRESS-Huffman, LZ4, zstd1 и проверяет полное восстановление байтов из локальных контейнеров.
2. **Отдельная VM, опционально драйвер:** те же скопированные страницы проходят kernel RAW/XPRESS PUT/GET/RESET. Проверяются восстановление всех байтов, requested allocation counters и задержки IOCTL. Отдельный random negative control не заменяет результаты приложений.

**Оба режима НЕ освобождают оригинальные страницы Edge/Chrome/Telegram.** Это проверка сжимаемости образцов и пути хранения, не прозрачная оптимизация памяти приложения, не тест ускорения и не доказательство экономии физической RAM. `physical_ram_saved_bytes` остаётся null/пустым, а не «0 подтверждённой экономии».

Native драйвер ранее прошёл 4042 синтетических проверки и штатный unload/reload на **Windows Server 2025 x64**, restricted-token ACL (не отдельная обычная учётная запись). Windows 11, HVCI, Driver Verifier, HLK, длительный stress и stock MSBuild не квалифицированы. **Новый 0.25.0 application/kernel-sample путь ещё требует запуска на Windows с вашими приложениями.** См. `driver/verification/REPORT.md` и `QA.json`.

## 1. Обычная установка программы — драйвер не нужен

### Требования

- Windows x64: целевая Windows 11 или лабораторная Windows Server 2025 с GUI. Windows ARM64 / 32-bit приложения в этом тесте не поддерживаются.
- Для capture — хотя бы 512 MiB свободной RAM; лучше 2 GiB и несколько GiB свободного диска. До 80 MiB исходных копий за два раунда плюс несколько контейнеров: временное потребление диска/памяти существенно больше 80 MiB.
- Edge, Chrome и/или Telegram Desktop **на том же компьютере и в том же Windows-сеансе**, native x64. Web Telegram внутри браузера считается браузерными данными, не Telegram Desktop.
- .NET 8 runtime включён в self-contained пакет; Python, Visual Studio, WDK и драйвер для режима 1 не нужны.

### Шаги

1. Скачайте приложенный **ElasticMem-v0.25.0-win-x64-research.zip** и SHA256.txt. Это локальный исследовательский выпуск; он **не опубликован** в публичном updater. Не обновляйте его кнопкой публичного обновления: там может быть другой/старый выпуск.
2. Полностью закройте старую программу, её агент и тесты. Не запускайте две копии одновременно.
3. При желании сохраните старую папку как резервную. Распакуйте новый ZIP целиком в новую папку, например `C:\ElasticMem-025`. Не смешивайте EXE/DLL из разных версий.
4. Проверьте SHA256 скачанного ZIP в PowerShell:
   ```powershell
   Get-FileHash 'C:\Downloads\ElasticMem-v0.25.0-win-x64-research.zip' -Algorithm SHA256
   ```
   Сравните с приложенным SHA256.txt. Hash подтверждает целостность, не безопасность/сертификацию.
5. Запустите `ElasticMem.exe`. Сначала обычный запуск; для своих приложений elevated может не потребоваться. Если нет доступа — лучше обеспечить одинаковый уровень запуска приложений и теста. Не включайте SeDebugPrivilege, не обходите protected process и не отключайте защиту Windows.
6. Версия должна быть **0.25.0**. Сведения о сборке/commit — BUILD.json/QA.json.

Если Windows/антивирус блокирует исследовательский файл, не отключайте Defender/SmartScreen: проверьте SHA, происхождение и политику, остановитесь при сомнении. Этот EXE не заявлен как production signed release.

## 2. Подготовка приложений

1. Откройте несколько обычных вкладок Edge и Chrome; дождитесь загрузки. Запустите Telegram Desktop x64 и откройте несколько чатов. Лучше тестовые профили и несекретные данные.
2. Тест читает память, где **могут быть пароли, токены и переписка**. Согласие обязательно. Пользуйтесь приложениями обычно; не закрывайте выбранные процессы между двумя снимками.
3. Только текущий сеанс и подтверждённые процессы: максимум 2 renderer Edge, 2 renderer Chrome и 1 Telegram, по 8 MiB на процесс в каждом из двух раундов. PID/время старта фиксируются; исчезнувший процесс не заменяется другим.
4. Браузер renderer не равен гарантированно одной вкладке. Browser main/GPU/utility, shared/image/mapped и неподходящие страницы не входят в основную выборку.
5. Не нажимайте «Проверить всё»/trim-режим для этого вопроса: здесь нужна конкретная кнопка теста реальных приложений. Если выбранное приложение отсутствует или недоступно — `unavailable_not_measured`, не синтетический «успешный тест».

## 3. Проверка без драйвера — рекомендуемый первый запуск

1. Откройте вкладку **Лаборатория**.
2. Выберите **Все: Edge / Chrome / Telegram**, либо отдельное семейство.
3. Нажмите **«Проверить реальные приложения: Edge / Chrome / Telegram»**.
4. Прочитайте предупреждение и подтвердите локальное чтение памяти. Автоустановки, авто-elevation и передачи данных по сети нет.
5. Программа выполняет selftests, read-only environment probe, затем два снимка с паузой **15 секунд** между раундами. Если memory compression ОС включена, тест её не выключает.
6. Дождитесь конца; откроется папка с ZIP логов и SHA256 рядом с ним. Кнопка отмены даёт частичный, а не успешный полный результат.
7. Для сравнимости повторите тест 3 раза при похожей нагрузке. Это повторные описательные наблюдения, не независимый randomized A/B и не тест application throughput.

### CLI (без драйвера)

Из папки программы в PowerShell:
```powershell
$p = Start-Process '.\ElasticMem.exe' -ArgumentList '--research applications --allow-memory-read --application all --out "C:\ElasticMem-025\applications-run.txt"' -Wait -PassThru
$p.ExitCode
```
`--application`: `all`, `msedge`, `chrome`, `Telegram`. Exit0 означает успешные доступные образцы; **не гарантирует наличие всех трёх семейств** — прочитайте coverage и unavailable. Exit1 — ошибка/частичный результат/нет измеренных приложений. `applications-run.txt` указывает ZIP.

## 4. Где логи и что можно отправить

По умолчанию `%LOCALAPPDATA%\ElasticMem\research-batches\<timestamp>-applications\` (точный путь показывается программой). Внутри `runs` лежат отдельные измерения; итоговый ZIP находится рядом, не внутри папок снимков.

В **logs-only ZIP**:
- `EXPORT.json`: hashes экспортированных файлов, статус проверки исходных manifests; `sensitive_data_included=false`.
- `manifest.json`: версия, commit, параметры, OS/runtime, executable SHA, статусы и список артефактов.
- `applications-report.txt`: понятный итог, доступность каждого семейства, сжатие/задержки.
- `application-compression-summary.csv`: сводка по приложению/PID/раунду/backend/codec; input/stored bytes, коэффициент, уменьшение представления, latency, full-byte verification.
- `result.json`: структурированные данные и явные null для physical RAM saving/application speedup.
- `codec-samples.csv`: user-mode микрометрики (us/block).
- `residency-summary-<PID>.json`: coverage, классификация и rejected/unreadable страницы, zero pages, pre/post WS/commit/fault counters. Эти изменения **не причинная экономия**.
- `kernel-samples.csv`: только при kernel-режиме; RAW/XPRESS payload, requested pool allocations, compressed/raw pages, 4 полных GET прохода, PUT/GET p50/p95/p99 (us/page), RESET baseline.
- environment probe и ошибки/отмена, если были.

**ZIP не содержит** сырые `pages.bin`, page-level адреса, словари, `.ecb/.emd` контейнеры, скриншоты, чаты или полные дампы. Но логи содержат PID, времена и сведения об окружении: просмотрите архив перед отправкой. Некоторые manifests содержат hashes/относительные имена исключённых локальных артефактов; это не их содержимое. Hashes экспортированных отредактированных логов находятся в EXPORT.json; hashes оригиналов в manifest могут отличаться из-за удаления пути профиля.

Перед отправкой можно проверить целостность экспортированного ZIP без распаковки:
```powershell
.\driver\scripts\Verify-Logs.ps1 -Path 'C:\path\ElasticMem-logs-....zip'
```
Этот новый helper ещё не запускался на Windows; экспорт/исключение снимков проверены portable unit tests. Он проверяет EXPORT.json, размеры/hashes и отсутствие unindexed files, не доказывает корректность измерения.

**Сырые снимки и контейнеры остаются на вашем диске**, в исходной batch-папке. После проверки и копирования ZIP закройте приложение и удалите исходную batch-папку, если не нужна. Обычное удаление не гарантирует secure erase. Не отправляйте папку `runs`, полный «sensitive export», RAM dump или весь диск VM.

## 5. Как читать результаты

- `serialized_roundtrip_checked` / `full_bytes_verified=true`: восстановленные копии совпали с исходными байтами; это критерий корректности, не освобождения RAM.
- User-mode `stored_bytes_kind=serialized_plus_model_reserve_not_RSS`: контейнер с metadata/padding и модельным reserve, **не resident working set**.
- Kernel `session_requested_pool_not_RSS`: запрошенные allocation sizes сессии, не физические страницы и не полный расход client+kernel.
- `ratio_input_to_stored = input_bytes / stored_bytes`; >1 — меньше представление выбранной копии. Отрицательный reduction допустим и означает overhead.
- Kernel `session_allocation_reduction_vs_raw`: сравнение XPRESS и RAW на **одних байтах**; это не уменьшение памяти приложения.
- User-mode p50/p95 — us/block; 16 KiB блок нельзя напрямую сравнивать с 4 KiB page. Kernel p50/p95/p99 — us/page IOCTL, allocation/copy/codec included, equality check/wipe excluded, three warmed read passes.
- `physical_ram_saved_bytes=null`, `application_speedup=null`: **не измерено**. Не суммируйте sampled проценты по всему приложению/системе.
- Недоступная цель, слишком мало eligible pages, PID change, cancellation, codec mismatch и driver error — не успешный результат. Отправьте logs-only ZIP с ошибкой.
- Random kernel control должен показывать raw fallback/overhead для несжимаемых данных. Это диагностический отрицательный контроль, не доказательство измерения браузера.

## 6. Опциональная установка драйвера — ТОЛЬКО disposable VM

Не нужна для раздела 3. **Не устанавливать на основной ПК**. Новый packet содержит unchanged native SYS из успешного Server 2025 теста; новый application sample client пока не Windows-qualified. Старые `kernel-cross`/`kernel-cross-UNSIGNED` SYS запрещены: LLD-путь отказал, экспериментальное исправление вызвало BSOD.

### 6.1 Подготовка
1. Создайте disposable Windows x64 VM с GUI и **checkpoint/snapshot**, доступом к консоли/recovery. Для повторения опубликованного smoke — Windows Server 2025 Evaluation; Windows 11 остаётся отдельной непроверенной конфигурацией. VM должна иметь достаточно RAM для ОС и приложений (практически лучше 8 GiB+, если позволяет host).
2. Установите в ней x64 Edge/Chrome/Telegram через официальные разрешённые каналы и тестовые профили. Не перенесите production-пароли.
3. Распакуйте пакет 0.25.0. SYS: `driver-native-UNSIGNED\ElasticMemStore.sys`, скрипты: `driver\scripts\`.
4. SHA unsigned SYS **до подписи** должен быть:
   `5362244d0d4d0724312ee3e403303190448fbdaf108b3d2a4a3a4b2cd6cea8a5`.
5. SYS в архиве **UNSIGNED**. Установка сразу должна быть отвергнута; VM-подпись из моих тестов и её private key не передаются. Production требует принятого Windows driver-signing pipeline; локальная test signature его не заменяет.

Если PowerShell запрещает выполнение `.ps1`, проверьте `Get-ExecutionPolicy -List` и используйте согласованный с администратором процесс исполнения/подписи скриптов. Не применяйте постоянный Bypass/Unrestricted и не обходите managed policy. EXE и обычный codec-тест не требуют изменения execution policy.

### 6.2 Разрешённая локальная тестовая подпись

Только если вы управляете этой **disposable VM** и её политика разрешает штатный test-signing. В elevated PowerShell:
```powershell
bcdedit.exe /enum '{current}'
bcdedit.exe /set '{current}' testsigning on
```
Если команда отвергнута Secure Boot/managed policy — **остановиться**, не отключать Secure Boot/HVCI/signature enforcement, не добавлять `nointegritychecks`, не использовать отключение проверки подписи через меню загрузки. Если команда разрешена — перезагрузите VM штатно. Этот режим не переносится на host.

После перезагрузки в elevated PowerShell из папки пакета:
```powershell
.\driver\scripts\Sign-ResearchDriver.ps1 -Path .\driver-native-UNSIGNED\ElasticMemStore.sys -ResearchVM
Get-AuthenticodeSignature .\driver-native-UNSIGNED\ElasticMemStore.sys
```
Helper проверяет exact unsigned hash, уже включённый test-signing, создаёт VM-local non-exportable RSA key и публичный сертификат, добавляет public Root trust и подписывает SYS. Сам не меняет boot policy и не устанавливает службу. Новый helper написан по проверенной процедуре, **сам helper в Windows ещё не запускался**. Если получено не `Valid`/AccessDenied — не продолжайте; сохраните ошибку и используйте ваш разрешённый signing process. Не ослабляйте ACL сертификатов и не отключайте security controls.

Не отправляйте private key/PFX. `.test-public.cer` — публичная часть, но её установка на другой ПК не нужна и не предусмотрена. После подписи SHA файла закономерно изменится; исходный SHA относится к unsigned файлу.

### 6.3 Установка и synthetic smoke
```powershell
.\driver\scripts\Install-SignedDriver.ps1 -Path .\driver-native-UNSIGNED\ElasticMemStore.sys -ResearchVM
.\driver-client\ElasticMem.DriverClient.exe info
.\driver-client\ElasticMem.DriverClient.exe smoke .\kernel-smoke-local.json
```
Installer требует elevated Admin и `Valid` signature, создаёт ограниченный SYSTEM/Admin каталог `%ProgramData%\ElasticMemDriver`, demand-start service (не auto-start), затем штатный `sc start`. Security policy не меняет. Если Windows отвергла загрузку — остановитесь, не обходите политику. Kernel smoke проверяет собственные синтетические страницы, **не приложения**.

Не запускайте импорт сертификата в TrustedPublisher ради этой ручной non-PnP установки: в проверенном тесте было достаточно Root trust + embedded test signature. Производственный/иной installation pipeline может отличаться.

### 6.4 Реальные копии Edge/Chrome/Telegram в kernel
1. Запустите приложения в той же VM и текущем сеансе. Откройте `ElasticMem.exe` elevated (само приложение не делает auto-elevation).
2. **Лаборатория → выбор семейства → «VM: копии приложений → kernel RAW/XPRESS»**.
3. Подтвердите VM checkpoint и чтение памяти. Порядок: selftests → environment → synthetic random control → два real-app captures. Один snapshot используется для user-codecs и kernel RAW/XPRESS.
4. При отказе driver control тест не продолжает capture и не подменяет backend; ошибка попадает в ZIP.
5. Итог: смотрите `kernel_comparison.rows`, `kernel-samples.csv` и сводный CSV. Оригинальные страницы приложения остаются; kernel pool добавляется. Это **НЕ end-to-end RAM A/B**.

CLI elevated:
```powershell
$p = Start-Process '.\ElasticMem.exe' -ArgumentList '--research applications --allow-memory-read --application all --kernel-samples --research-vm --out "C:\ElasticMem-025\kernel-applications-run.txt"' -Wait -PassThru
$p.ExitCode
```
Без `--research-vm` kernel sample режим отвергается. Флаг — ваше подтверждение, не автоматическое доказательство, что ОС находится в VM.

## 7. Выгрузка, удаление, откат

1. Завершите измерения и закройте все клиенты устройства, включая ElasticMem и CLI.
2. Elevated PowerShell:
   ```powershell
   .\driver\scripts\Uninstall-Driver.ps1
   ```
   Это штатный stop/delete; принудительный unload недопустим. SYS сохраняется для инспекции. Если handles активны и stop недоступен — сначала закройте их; не удаляйте файл у загруженного драйвера.
3. Папку `%ProgramData%\ElasticMemDriver` inspect/remove вручную **после успешной выгрузки/удаления службы**, если нужно переустановить: installer откажет при существующей папке.
4. Лучший полный откат trust/test-signing/ключей — restore VM checkpoint или удаление disposable VM. Для ручного возврата test-signing отключают штатно `bcdedit.exe /set '{current}' testsigning off` и перезагружают уже после удаления тестового драйвера; не затрагивайте чужие сертификаты.
5. Если BSOD — восстановите checkpoint, не загружайте драйвер автоматически. Можно сохранить BugCheck code, параметры и Event log; полный memory dump может содержать пароли и private keys, **не отправлять его**.
6. Обычная программа portable: закройте её, сохраните logs-only ZIP и удалите папку распаковки. Данные в `%LOCALAPPDATA%\ElasticMem` удаляйте отдельно после просмотра; отсутствие драйвера не означает удаления снимков.

## 8. Самостоятельная сборка (не обязательна пользователю)

- .NET SDK **8.0.426** pinned в global.json; VS 2022 Desktop C++, SDK/WDK10.0.26100, KMDF1.33 для штатного driver build.
- `driver\scripts\Build-Windows.ps1` — рекомендуемый stock MSBuild путь, в нашей лаборатории ещё не запускался.
- Linux `cross-build.sh` создаёт только COFF objects, не installable SYS. `Native-Relink.ps1` использует официальный Microsoft link.exe `/dll /driver`; сам новый wrapper не runtime-qualified. Native-команда с теми же C objects прошла Server 2025 smoke, но имеет LNK4078 (.data attributes).
- Любая пересборка даёт новый артефакт и требует собственной подписи, VM tests и qualification. Не переносите passed статус старого exact SYS на другой build.

## 9. Что прислать для проверки

**Logs-only ZIP + соседний `.sha256`** каждого из 2–3 повторных запусков; отдельно `kernel-smoke-local.json`, если проверяли VM-драйвер. Напишите, какие приложения действительно были запущены, выбранное семейство и использовался ли driver. Не присылайте сырую память, sensitive export, переписку, private key или диск VM.
