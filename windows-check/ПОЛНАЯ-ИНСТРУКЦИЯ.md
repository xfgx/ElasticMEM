Либо распаковать https://citpmcpmy.eastus.cloudapp.azure.com/elasticmem/ElasticMem-v0.21.0-win-x64.zip в новую папку и запустить ElasticMem.exe, закрыв старый экземпляр.

Исходники/git.bundle: https://citpmcpmy.eastus.cloudapp.azure.com/elasticmem/ElasticMem-v0.21.0-source.zip .

## 2б. Microsoft Edge / Chrome на другом компьютере
**Проверяется только компьютер, на котором запущен ElasticMem**, в текущем Windows-сеансе. Браузер, из которого вы пишете сообщение на другом ПК, приложение не видит. Установите/обновите ElasticMem на том ПК с Edge, который нужно проверить. Удалённый доступ и передача памяти по сети не добавлены.

1. Откройте на проверяемом ПК **2–4 обычные вкладки Microsoft Edge** с разными сайтами, не закрывайте их во время проверки. Спящие/завершённые/недоступные renderers могут не подойти; соответствие «вкладка=процесс» не гарантируется.
2. **Лаборатория → Браузер на этом ПК → Только Microsoft Edge (msedge.exe)**. Для Chrome — «Только Google Chrome».
3. Нажмите **Проверить Chrome / Edge (коротко)**. Это согласие на локальное чтение до64МиБ снимков выбранных рендереров; они могут содержать секреты. Сам агент остановится. Этапы: окружение/самопроверка,15с счётчиков выбранных renderer PID,свежий Г1,Г4-кодеки и ZIP. Дополнительное время зависит от чтения/кодеков, это не обещание завершить весь запуск за15с.
4. **Trim браузера, долгие эпохи, собственный controlled, дисковый/GPU тесты не запускаются**, даже если в интерфейсе стоит галочка trim: короткая кнопка её не использует. Настройки Windows не меняются.
5. Пришлите автоматически созданный ZIP. Если пары рендереров нет, будет skipped с причиной; процесс не заменяется браузером другого семейства или самим ElasticMem. В report/result записаны предпочтение, подтверждённые семьи/PID и область «этот ПК».

В режиме «Авто: Microsoft Edge, затем Chrome» используется доступная пара Edge; если её нет — пара Chrome. Один Edge renderer не блокирует выбор пары Chrome. Автовыбор больше не предпочитает Steam из-за большего WS; Steam-контроль остаётся только явно указанным CLI `--browser steamwebhelper`/ручными PID. Явный выбор Edge **никогда** не заменяется Chrome/Steam. Роль renderer/native-x64/session/lifetime guards сохранены. Отказ/закрытие выбранного семейства после обнаружения не означает разрешение на смену семейства.

CLI короткого запуска (не запускайте вторую копию GUI одновременно):
```bat
ElasticMem.exe --research auto --browser-only --browser msedge --allow-memory-read --seconds 15 --out edge-report.txt
```
`--browser-only` несовместим с `--extended` и `--allow-working-set-trim`; отказ до запуска проверок. Без `--allow-memory-read` снимки пропускаются. Параметр `--browser` применяется к автоматическим запускам, не переопределяет ручной список PID.

## 2а. Контроль 0.21 — без браузера
1. Остановите агент сжатия и другие тесты ElasticMem. Оставьте хотя бы512МиБ свободной RAM.
2. Откройте **Лаборатория → Контроль доступа (без браузера)**. Это отдельная кнопка: PID, снимки браузера и галочка разрешения trim рендереров не нужны.
3. Дождитесь окончания (обычно около20–60секунд; тайм-аут child180секунд, обработка результата может занять дополнительное время). Не запускайте параллельно старый экземпляр приложения.
4. Откроется папка с автоматически собранным ZIP. Пришлите **этот ZIP целиком**, даже если результат failed/unsupported или много unknown. Обычный экспорт не содержит приватный файл IPC из inputs.
5. После этого, если нужны новые данные браузера, можно отдельно запустить полную автоматическую проверку ниже. Новый контролируемый этап входит и в неё.

### Что проверяет короткая кнопка
Приложение создаёт только собственный дочерний процесс:128 native-страниц(512КиБ),256 логических эпох на каждую из трёх заранее заданных нагрузок и отдельный lifecycle-контроль. Между эпохами sleep20мс — это **не256секунд наблюдения браузера**. Есть коррелированный interleaved контроль, соседний коррелированный контроль и seeded независимый fixed-density контроль. В первых трёх фиксированных контролях выделение сохраняется на всю трассу: освобождений/перераспределений внутри них нет. Отдельный lifecycle-контроль описан ниже.

### Новый отдельный lifecycle-контроль 0.21
Та же кнопка выполняет дополнительный own-child тест128страниц/256логических эпох: одна reservation остаётся на весь тест, страницы decommit/recommit по заранее фиксированному плану. При каждом новом commit увеличивается логическое поколение, записывается полная страница и generation-marker. Контрольная сумма scheduled volatile reads независимо сверяется parent по плану/поколениям. Это не произвольный адрес allocator и не доказательство идентичности физического frame.

Измерение начинается **после** переходов и инициализации. Сохраняются logical-index карты alive/touch/pre/postValid и поколения (не native addresses/пользовательские данные). Inactive generation0 — reserved/никогда не committed; это НЕ смерть страницы. Dead generation>0 устанавливается только успешным собственным MEM_DECOMMIT, не исчезнувшим mapping/QWS-ошибкой. Reserved-only, post-decommit dead, retained-active unknown и known-active FN/FP имеют отдельные счётчики и раздельные Valid-аномалии. API-ошибка прерывает worker, не записывается как0касания. Valid на dead-странице — отдельная аномалия, не ложное срабатывание среди live. Встроенных frees/reallocations в прежние три фиксированных Г5-контроля не добавлено.

**Г5 на lifecycle-трассе явно skipped:** текущая модель не поддерживает смерть/смену поколения; она не получает поддельную «точную» непрерывную identity. Тест пока проверяет наблюдение и generation integrity, не полезность блока/плотность под churn/реальный браузер. Linux-тесты сверяют план, знаменатели и испорченные IPC-фикстуры; native decommit/recommit требует вашего Windows ZIP. Весь controlled займёт дольше прежнего (ещё256×20мс плюс API/обработка).

После trim **только своего child** стенд явно читает первое64-битное слово каждой запланированной страницы через volatile read. Эти программно известные обращения — ground truth **только выделенной арены**, не точная трасса всего процесса. QWS до/после чтения сопоставляется с этой историей. Retained-after-trim остаётся unknown, не «нет обращения» и не death. В отчёте отдельно: доля known, conditional FN/FP/recall, unknown TEST epochs и счётчики по эпохам. Нули FN при низком known не доказывают точность по всем страницам.

Неизменённый каузальный Г5 запускается отдельно на известной синтетической истории и на Windows proxy. Первичные сравнения заранее фиксированы: **T2, блоки4/16страниц**; другие пороги — exploratory. Строгие unknown/gate/minimum30 правила браузерных трасс не ослаблены. Synthetic positive — проверка механики, **не доказательство выигрыша Chrome/Steam или физической RAM**. CPU — прогретый sampled decode/copy, не полный paging; timing на synthetic payload не переносится на браузер. Истории truth/proxy с разной missingness не являются парным измерением ускорения.

Отмена/тайм-аут завершают только Process, который приложение само создало; другие процессы не ищутся и не уничтожаются. Pagefile, MemoryCompression и PageCombining не меняются. Native Windows-часть требует реального прогона: Linux QA подтверждает сборку/чистые функции/фикстуры, но не этот runtime.

## 2. Одна кнопка
1. Откройте несколько обычных вкладок Chrome/Edge либо Steam-клиент: нужны2–4 читаемых native-x64 **рендерера одного семейства**. Программа не запускает нагрузки за вас. Уже работающие Python/Node/Steam могут попасть в отдельное read-only наблюдение.
2. Закройте игры перед GPU-тестом, другие экземпляры ElasticMem и старые бенчмарки. Не выбирайте античит/защищённые процессы. Оставьте запас свободной RAM.
3. **Лаборатория**: **Расширенный Г0/Г5** включён по умолчанию. Без trim —10минут read-only наблюдения, около минуты собственной CPU-калибровки и остальные проверки.
4. Для Г0-epochs/Г5 поставьте **Г0: разрешаю trim ВСЕГО рабочего набора рендереров каждую секунду**. Изначально галочка снята! Вмешательство может вызывать задержки; cap ограничивает опрос, **не действие EmptyWorkingSet**. С расширенным режимом добавится не менее10минут на каждый из2–4рендереров: ориентировочно30–55минут всего, при медленном опросе дольше. Если нельзя мешать браузеру — галочку не ставить.
5. Нажмите **Проверить всё — автоматически**. Это согласие на локальное чтение до128МиБ суммарно (до64МиБ исходных и до64МиБ свежих снимков) памяти рендереров. Снимки могут содержать пароли/переписку; в обычный ZIP не входят. Агент остановится и после партии останется остановленным.
6. Работайте как обычно, не закрывайте выбранные процессы. По завершении откроется папка ZIP. Итоговый текст уже содержит размеры Г4, виртуальные V(T)/R(T), полезность Г5 и GPU/дисковые медианы.

Кнопка **Проверить всё (читает память)** в главном окне использует настройки Лаборатории.
Для короткой проверки снимите расширенный режим:120с наблюдения; при согласии trim —12эпох на максимум2рендерерах и bounded subset. Это проверка механики, не исследование объёма.
**Отменить** сохраняет частичные данные с неуспешным статусом. Закрытие ждёт остановки работы; GPU timeout может потребовать перезапуска. Submitted ресурсы не освобождаются преждевременно.

## 3. Автоматические этапы
- **Окружение**, затем повторный probe: read-only Get-MMAgent/RAM/ОС. Видимый working set MemCompression **не равен compressed payload**. Недоступные payload/логический объём/ratio —null, не0. Кодек конкретной Windows-сборки по общему ratio не определяется.
- **Самопроверка**: кодеки/контейнеры/mappings/models/export/bitpacked epochs; на Windows native Xpress/Huffman. При ошибке зависимые этапы skipped.
- **Контроль доступа0.21**: отдельный lifecycle decommit/recommit с поколениями и known/dead/unknown; lifecycleГ5skipped. собственный child и известные volatile reads; отдельные truth/proxy replay, заранее фиксированные T2/cap4,16. Синтетический контроль, не эффект на браузере.
- **Г0-счётчики**: до5 уже работающих Chrome/Edge/Steam/Python/Node, по возможности разных типов. При отсутствии —observer-only. Этот широкий список **никогда не используется для trim/снимков**. PageFaultCount объединяет soft/hard faults; это не SSD-трафик или page-access trace.
- **Калибровка**: собственный child32МиБ;10paired rounds baseline/trim/trim+query по2секунды, ротация порядка. CPU/faults/operations/s; bootstrap5000resamples целых paired rounds,seed17. Интервал описательный: зависимость/дрейф не исчезают.
- **Own post-trim reads**: до256касания с timing/counters. Предварительная Valid может измениться. Backing origin **unknown: standby/compressed/pagefile**; это не latency Xpress/pagefile. Отдельный fault-origin этап skipped с причиной, без искусственного memory pressure.
- **Г1**: свежие2–4рендерера, до16МиБ/PID. Residency/mapping/lifetime guards до/после чтения; invalid/image/mapped/shareable исключены. Brotli-only/raw dedup/закрытый ordinal-normalization контроль; снимок не атомарен.
- **Г4**: plain Xpress, Huffman, LZ4, zstd-1 4К, zstd+dictionary4К, zstd16К. Train на первом PID, test на других; counted dictionary,24Bbindings,16Bheaders,8Bpadding,256Ballocation,8%reserve. Fresh decoder из сериализованного словаря проверяет PID/address/байты. Ratio —модель хранилища, не RSS. Gate25% —относительно plain Xpress; Huffman дополнительный ориентир. Stored restore второй/прогретый decode, не full paging;16К восстанавливаются целиком.
- **Г0-epochs/Г5**: только с отдельным согласием; методика ниже.
- **Диск QD1**: независимо от GPU; собственный новый TEMP-файл32МиБ, random aligned unbuffered reads4/64/256КиБ,100измерений после10warmups, stale-generation/wrong-offset negatives. Delete-on-close, существующие файлы не меняются. Bus/media **не подтверждены как NVMe**; cache накопителя остаётся. Seek и сравнение вне timing. Это не реальная pagefile-fault latency.
- **Г3**: software/UMA исключены. DEFAULT→READBACK copy queue4/64/256КиБ, restore/roundtrip/p50/p95/p99,6negative checks. GPU_UPLOAD/ReBAR для DMA не нужны. Пул32МиБ≤25%доступного WDDM budget; residency/durability не гарантированы.40мкс —исторический screening, не измеренная NVMe-планка. Старый GPU_UPLOAD путь отдельный.
- **Г2**: собственные fixed-schema records, не CPython/V8 patch.
- **UI**: механический bounds audit двух тем при текущем DPI; ноль warnings не визуальная приёмка.
- **Экспорт**: source-run hashes проверяются до ZIP; exported bytes получают отдельные SHA256.

Exact trace/Belady skipped. Synthetic churn в auto skipped до независимого решения по объёму; доступен вручную как контроль. Kernel pager не включается.

## 4. Расширенный Г0 и Г5
Г0: первичный VirtualQueryEx census committed/readable MEM_PRIVATE, включая нерезидентные **адреса без чтения их содержимого**. До262144опрашиваемых страниц/PID(1ГиБ виртуального диапазона); при cap address-prefix, не random. Scan stop/cap/coverage отражаются отдельно. MEM_IMAGE/MAPPED/guard/noaccess исключены.
На каждом renderer: baseline4 →trim4 →trim+residency600эпох; nominal1с, модель использует измеренные длительности. Перед каждым trim подтверждаются handle-bound image/native-x64/renderer/session/lifetime. Командная строка не сохраняется. Новые mappings после census не добавляются; одинаковый AllocationBase не доказывает отсутствие reuse.
Модель Г0 0.18 использует initially-resident AND all-known последовательности; отдельно replay считает newly-observed с активацией при первом возврате; excluded/retained coverage выводится. Это survivorship-biased residency proxy, не exact touches/unique frames/desktop ceiling. V(T) —виртуальные байты модели; R(T) —наблюдаемые reacquisitions. Стоимости10/20/40/100мкс —сценарии, не измеренные fault costs. Нельзя объявлять V экономией сверх standby/compressed store.
Расход истории ограничен: если оценка превысит половину свободной RAM либо свободная RAM упадёт ниже512МиБ, остановка с причиной вместо pressure. Pagefile/MemoryCompression/PageCombining не меняются.

Г5: локальные private `.eet` содержат PID/lifetime/addresses/activity и known bitmap каждой эпохи. Cohort —train-known пересечение с предшествующим снимком,≤4096страниц/PID, **не фильтр по будущему test**.
Три замороженные группы до4страниц: address adjacency; train coaccess(до64spreadepochs внутри первой половины,Hamming greedy); static content histogram(dominant byte/zero/FF,не semantic model).
Кодек zstd-1/16К одинаковый. Сериализованные bindings/bytes проверяются fresh decoder; counted metadata/alignment/reserve. Ratio одного предшествующего снимка, не churn.
Test —вторая половина. Полезность = distinct pages, наблюдённые в trigger epoch и следующей эпохе(N=1). В этом окне повторный decode не начисляется. Декодируется весь блок; decoded/useful counts/fraction выводятся. Нет cache-capacity модели.
Unknown test windows исключаются с coverage, не превращаются в inactive; при любом unknown suffix continuation gate=null. Положительный gate требует mean coaccess≥2 **и** >adjacency на полностью известных данных. Недостаток событий —нет вывода, не победа. Residency reacquisition не доказывает реальные co-access/page misses.
Критерий ≥1ГиБ сверх штатных механизмов при10мс/с/процесс —решение исследования, **не вывод этого proxy** без counterfactual standby/store.

## 5. Ручные режимы
Выберите режим→параметры→**Запустить проверку**.
- **Г0-epochs/Г4**: source folder успешного локального Г1 со snapshots.
- **Г5**: source folder успешного Г0-epochs0.17+ с inputs/epochs-*.eet и copied pages/inventory. Hashes, PID/lifetime/offsets проверяются. Logs-only ZIP недостаточен.
- **Г4 churn**: собственные64страницы/256seeded alloc/free/write,blocks4/16К; живые bytes проверяются после каждого изменения, dead logical slots/payload rewrites считаются. Не real renderer churn/physical RSS/paging latency.
- **Диск QD1**: выбрать папку нужного диска; сравнение file I/O с GPU, но не доказательство NVMe/pagefile attribution.
- **Г0 exact model**: внешний exact/synthetic CSV map/read/write/unmap+metadata. Counters/DAMON/page_idle/EET не relabel exact.
- **UI screenshots**: отдельная кнопка сохраняет локальные снимки; включение в sensitive export —только осознанно.
Старый **Агент сжатия** изменяет WS через Windows; уменьшение WS не равно RAM savings. Не совмещать с исследованиями; active window/игры по умолчанию исключены. Прочие старые бенчмарки не новый kernel compressor.

## 6. Где ZIP и что прислать
После auto откроется `%LOCALAPPDATA%\ElasticMem\research-batches\<партия>\`. Пришлите **ElasticMem-logs-*.zip**, не всю runs/.
Обычный ZIP исключает пользовательские snapshots/адреса/входные трассы/словари/`.ecb/.eet/.emd/.erb`/screenshots. Включает агрегаты, timing CSV, manifests, auto-report. Исключение: созданные самим controlled-тестом синтетические logical-index bitmaps и поколения включены в result.json; они не содержат native адресов и данных чужого процесса. Просмотрите перед отправкой: PID/process/hardware/error могут быть личными. Экспорт не гарантированно анонимен.
На test1 разработчик автоматически публикует **только релиз приложения**. Приложение не отправляет ваши ZIP/страницы/трассы в MCP/на сервер.
`completed_with_skips` требует просмотра причин. `unsupported` —нет измерения, не отрицательная скорость. `failed/invalid/cancelled` —не результат. SHA256 доказывает целостность, не методику/самодостаточное воспроизведение без private inputs. Частичный ZIP при export failure не принимать за успешный.

## 8. Пока не реализовано
Подтверждённая compression/standby/pagefile attribution и их latency; стабильный build-independent payload/logical-store API; counterfactual incremental savings; exact accesses/Belady/desktop ceiling; heterogeneous foreign trim; реальный renderer churn; kernel StorPort/pagefile driver; VRAM TDR/sleep durability/migration; CPU ReBAR/AVX path; semantic pointers; CPython/V8 patch; установленная новизна Г5.
Ничего из этого не подменяется QD1, WS, synthetic fixture или static ratio.
История: hotfix0.16.1 workspace Huffman прошёл native fixtures на пользовательском Windows-прогоне. В пользовательском0.17.0 native fixtures и DMA256К выполнены, но Г0 завершился отказом QueryWorkingSetEx, Г5 не выполнен. Исправление0.21.0 требует нового Windows-прогона.
## История исправления0.17.1
В пользовательском0.17.0 Г0 остановился на QueryWorkingSetEx с Win32 error5. Причина(живой handle/выход процесса/отказ API/размер batch) из старого лога не установлена. Теперь automatic запускает каждый renderer в отдельном sealed run; отказ одного PID остаётся failed в общей партии, но не отменяет попытки других PID. Г5 берёт только успешный завершённый источник с полным запланированным числом эпох, roster и identity/offset checks; сокращённая аварией трасса не получает новый split. Counters пишутся/flush по эпохам и сохраняются при ошибке; failure log содержит PID/phase/pre-or-post/batch/code/handle lifetime без адресов. Batch1024pages соответствует размеру прежнего G1, это проверяемое ограничение, не доказанное устранение Windows-отказа. Нет повышения привилегий/обхода защиты/retries denied PID. Для диагностики одного PID CLI: --research g0-epochs --epoch-pid <PID> вместе с источником/consent;0 означает прежний all-source manual режим. Новое поведение требует Windows rerun.

## 9. Новое в 0.21.0: сначала пересчёт, затем новый захват
### Пересчёт уже сохранённой партии 0.17.1 — одно нажатие
1. Обновите приложение, закройте старый экземпляр. Сохраните `%LOCALAPPDATA%\ElasticMem\research-batches` на своей машине: там локальные `.eet`, inventory и pages. Не удаляйте их после отправки ZIP.
2. Остановите агент и другие бенчмарки. **Лаборатория → Пересчитать последнюю партию (без trim)**. Выбирается последняя завершённая локальная автоматическая партия, не её экспортированный ZIP. При отсутствии полных входов будет явная ошибка, данные не подменяются.
3. Процессы не читаются и не trim-ятся; pagefile/MMAgent не меняются. Обработка больших карт может занять минуты и заметную CPU/RAM. До чтения карты действует guard: packed≤80МиБ, свободно≥512МиБ и оценка раскрытия/рабочих массивов не выше половины свободной RAM; иначе unsupported вместо давления на память. **Отменить** сохраняет неуспешный статус; не закрывайте приложение до остановки.
4. Откроется новая папка с `ElasticMem-logs-*-replay.zip`. Присылайте этот ZIP, не `.eet`/pages/весь research-batches. При ручном выборе режима **Г0/Г5 · локальный пересчёт карт** поле source принимает папку одного успешного Г0-epochs либо `auto-summary` завершённой партии; пустое поле означает последнюю партию.
CLI: `ElasticMem.exe --research epochs-replay --source-folder "C:\path\successful_G0_or_auto_summary" --out "%TEMP%\ElasticMem-replay.txt"`. Без source — последняя локальная партия. CLI сохраняет sealed run; ZIP — отдельный `--research export`, в UI создаётся автоматически.
### Что выводит пересчёт
- Г0: T=1,2,4,8,16,32,64,128,256 эпох; полные V/R, массив модельных промахов по эпохам, p99/max и число эпох после T. Цена10/20/40/100мкс, бюджет10мс/с/PID — сценарии, не подтверждённые fault latency. На коротких12эпохах большие T — мало/нет tail-наблюдений, не потолок.
- Новые захваты EETv3 сохраняют Valid перед первым trim в private-карте. Основная когорта initially-resident AND all-known. Изначально нерезидентные/позже наблюдённые — отдельная модель с активацией при первом возврате. Никогда не наблюдённые нерезидентные исключены. EETv2 из0.17.1 не имеет baseline: восстановить её задним числом нельзя; old replay сообщает unavailable, включает только ever-observed/all-known с активацией при первом возврате.
- Всплески: наблюдённые возвраты, p99/max, эпохи выше внутрипроходногоp95, страницы замеченные только в таких эпохах, описательная автокорреляция. Это **не атрибуция GC**: нет GC events/V8 heap labels, sampling не полная трасса.
- Каузальный Г5: ≤1024 TRAIN-observed/known snapshot pages, spread по адресному порядку. Train первая половина, test вторая; подписи только из прошлой training-половины, frozen. Блоки1/4/8/16страниц формируются только из одновременно холодных (idle≥T) страниц в конце эпохи; горячие партнёры запрещены. Политики adjacency/coaccess.
- Полезность — **только та же triggering-эпоха**, без зачёта будущего N=1 prefetch; поэтому числа не равны старым3.09/1.72. Любая unknown cell когорты исключает эпоху для всех политик, сбрасывает blocks/idle; unknown НЕ decommit. Gate unavailable при unknown, <30decode events у любой сравниваемой политики или отсутствующем mean. Для coaccess4 gate требует≥2.5 полезных и >adjacency; coaccess16≥8 и >adjacency. Это описательный offline screening, не runtime speedup.
- CPU/размер: первые128 фактических decode events каждой строки, payload из предшествующего snapshot; zstd1, raw-fallback, roundtrip каждого sample, медиана3 warmed decode/copy. `sampled_cpu_us_per_useful_page` только этого sample, не total CPU/pager. Подсчитаны header/bindings/padding/256B/8%reserve; allocator/runtime RSS и меняющееся содержимое отсутствуют. Блоки могут быть недозаполнены. Одностраничный контроль на той же когорте/эпохах.
### Новый прогон с baseline
После offline при необходимости **Проверить всё — автоматически** с расширенным режимом и отдельным разрешением trim. Сохраняются прежние2–4renderer allowlist, lifetime/session guards. Python/Node доступны только read-only counters; чужие heaps/GC не патчатся. Steam renderer допустим, native Steam/browser/GPU/network не trim-ятся. Replay нового источника входит в автоматическую партию.
### Калибровки и пределы автоматизации
Подсказка Task Manager «XМБ хранят YМБ» полезна для объёма/ratio: пришлите X/Y или снимок только панели Память, без других окон. Ratio **не идентифицирует кодек Windows**. Get-MMAgent unavailable — не означает compression выключено.
Подтверждённые compressed-store/pagefile/NVMe/RAMdisk fault latencies ещё unavailable. Own post-trim read и fileQD1 их не заменяют. Установка RAMdisk/драйвера, размещение pagefile на нём и отключение MemoryCompression **не выполняются**. Это отдельное вмешательство с резервным планом, проверкой совместимости и согласием, не безопасная часть одной кнопки.
Belady/exact accesses, GC attribution, actual decommit/churn, kernel pagefile/VRAM durability, дополнительная физическаяRAM сверх standby/compressedstore — **не реализованы и не заявлены**. `PrivateUsage−WorkingSetSize` не используется как «экономия Windows». Разновременные PID модели не суммируются как физическая память стола. GPU64К относится к transfer payload, не обязательно к64К исходных несжатых страниц; CPU/metadata/first-miss не исчезают при амортизации.


## 0.21.0: надёжность следующего прогона

### Куда нажимать
1. **Обновление → Проверить обновления → Установить**. Старый экземпляр закрыть.
2. Откройте несколько обычных вкладок одного браузера/Steam; дайте им загрузиться. Сохраните работу. Не закрывайте вкладки и не перезапускайте браузер до конца. Это уменьшает риск, но не гарантирует, что renderer проживёт весь прогон.
3. **Лаборатория**: оставить **Расширенный Г0/Г5**; отдельно поставить согласие на trim только если допускаете вмешательство во весь рабочий набор выбранных рендереров каждую секунду. Без галочки вмешательства в чужие рабочие наборы нет.
4. Нажать **Проверить всё — автоматически**. Дополнительный свежий снимок каждого выбранного renderer выполняется непосредственно перед его эпохами; подтверждаются исходный PID, creation time, сессия, native x64 и роль. Завершившийся/переиспользованный PID не подменяется новым.
5. После завершения прислать созданный обычный ZIP. Ничего вручную собирать не нужно. Если завершился процесс или есть unknown — прислать ZIP всё равно: ошибки и пропуски полезны для диагностики. Повторный офлайн replay тех же карт не является новой нагрузкой и не устраняет unknown.

### Что добавлено
- Первыми проверяются более старые экземпляры из уже выбранного списка. Это эвристика, не обещание стабильности. Свежий снимок уменьшает рассогласование старого содержимого и начала трассы; не даёт атомарного снимка или содержимого на момент каждого будущего промаха.
- **epoch-health.csv**: на каждую завершённую эпоху две строки — `census` и `snapshot_intersection_NOT_selected_G5`. Взаимоисключающие причины в порядке приоритета: исходный mapping недоступен; текущий mapping недоступен; AllocationBase изменился; страница осталась резидентной после trim; иначе known. Недоступный mapping **не равен доказанному decommit/смерти страницы**. `retained_after_trim` здесь считается после mapping-отказов; старый счётчик retained в epoch-counters считает все retained, поэтому они могут различаться.
- **epoch-health-PID.json**: агрегаты page-epoch cells, не число уникальных страниц. Нет адресов/содержимого. Это не точные причины unknown в TRAIN-selected Г5: указанная популяция шире; не переносить её проценты на выбранную когорту. В старых трассах причин нет — replay их не придумывает.
- Числовой отчёт: Г4 показывает выигрыш store **с резервом** против plain Xpress и достижение/недостижение 25% в текущей выборке; словарь сравнивается с plain zstd4K. 16К — иной размер единицы восстановления. Это не установление кодека Windows.
- Г0: исходная когорта, выбранные сценарии и средний бюджет отдельно от модельных p99/max всплесков. Никакой физической дополнительной RAM/Belady/GC-атрибуции. Конечные 600 эпох включают startup/right-censoring.
- Г5: unknown TEST epochs и недоступный gate видны прямо в итоговом тексте. Строгий gate **не ослаблен**. Unknown не трактуется как death.
- Г3: FILE/GPU — только отношение медиан собственных микротестов, отдельно restore/roundtrip; четверть FILE не означает выигрыш pagefile/NVMe или прохождение хвостовой задержки.

### Что не делается автоматически
Программа не отключает MemoryCompression/pagefile, не устанавливает RAM-диск/kernel/VRAM-pager, не включает PageCombining, не определяет backing ошибки по времени чтения. Нет безопасного основания объявлять выигрыш ≥1ГБ сверх Windows или строить драйвер. Python/Node/Steam-client входят только в read-only счётчики: trim по-прежнему ограничен подтверждёнными renderer chrome/msedge/steamwebhelper.

Сборка и Core/fixture/release-тесты на Linux — не подтверждение исполнения Windows API, GPU, интерфейса или отмены на вашей машине. Пользовательские логи/дампы остаются локальными: test1 получает только четыре артефакта выпуска, не данные памяти.


## 0.22.0 — реальные Chrome / Microsoft Edge / Telegram

### Одно нажатие
1. Обновите ElasticMem до0.22.0. Откройте на **той же Windows-машине** Edge/Chrome (обычные вкладки) и Telegram Desktop. Другой ПК не опрашивается.
2. Лаборатория → **«Проверить реальные приложения: Edge / Chrome / Telegram»** → подтвердите чтение локальных снимков памяти. Агент ElasticMem останавливается; дочитайте предупреждение о приватности.
3. Продолжайте обычную работу: переключайте вкладки, прокручивайте страницу/чат. Автотест выберет до2 native-x64 renderer PID каждого браузера и1 Telegram по начальному рабочему набору. Делает два снимка каждого выбранного PID с паузой15с между раундами. Нет необходимости вводить PID или подбирать файлы.
4. По завершении откроется папка с ZIP. Пришлите **ZIP логов**, не каталог snapshots, ECB, EET и не полный каталог приложения. Отправки по сети нет. Файлы памяти и контейнеры остаются локально; обычный ZIP их исключает.
5. Если приложение недоступно — будет «не измерено», а не нулевой выигрыш. Откройте приложение на этой машине и повторите. Завершённый/переиспользованный PID не заменяется другой целью. WOW64/ARM/другая сессия/защищённые процессы не поддерживаются. Telegram Web проверяется как renderer браузера, не как Telegram Desktop.

### Что проверяется реально
- Байты существующего приложения: pre/post guards ограничивают снимок resident/private/exclusive страницами; лимит8МиБ/PID/раунд, всего≤80МиБ. Адресный префикс — **смещённая ограниченная выборка**, не вся память приложения.
- Для каждого PID/раунда отдельно: plain Xpress, Xpress-Huffman, LZ4, zstd1 4К и zstd1 16К. Фиксированные кодеки без обучения и словаря: Telegram не требует второго процесса и не заимствует данные другого приложения.
- Сериализованный cold-store восстановлен новым декодером и сравнен побайтно; учитываются bindings, заголовки, padding,256-байтовое выделение,8% резерв. Это модель размеров, не physical RSS.
- Время warmed stored-payload restore (raw fallback учитывается), p50/p95 и CSV; для16К время относится ко **всему блоку16К**, не одной случайной4К странице. Parsing/I/O/pagefault/stack хранения не включены.
- Реальные WorkingSet и PrivateUsage до/после чтения снимка; они служат контекстом/проверкой возмущения, **не эффектом оптимизации**. Снимок не атомарен; pre/post guards не гарантируют отсутствия faults.

### Что не заявляется
**Это диагностика пригодности кодеков на реальных данных, не работающий прозрачный оптимизатор чужих приложений.** Их страницы продолжают жить в исходном формате; live reclaim, redirect faults, драйвер/pagefile и приложение сжатого store отсутствуют. Поля physical_ram_saved_bytes и application_speedup равныnull. Не экстраполировать проценты8МиБ на весь браузер/Telegram. Два раунда не являются независимым A/B; пользовательская активность не автоматизирована и скорость приложения не измеряется.

Нельзя честно ответить «стало быстрее/сэкономлено NМБRAM» до появления безопасного live backend и контролируемого функционального A/B workload. Копировать снимок в сжатый буфер и считать его размер реальной экономией — неверно; тест явно запрещает такую интерпретацию. Никаких trim чужих приложений, inject, изменения MemoryCompression/PageCombining/pagefile или kernel-драйвера данный режим не делает.

CLI (консоль/PowerShell):
```powershell
.\ElasticMem.exe --research applications --allow-memory-read --out applications-report.txt
```
CLI требует отдельного consent-флага, отвергает --extended и --allow-working-set-trim. GUI экспортирует ZIP автоматически, CLI тоже. Полная инструкция включена в приложение и пакет релиза. Linux-тесты и кросс-сборка не заменяют Windows runtime-проверку.
