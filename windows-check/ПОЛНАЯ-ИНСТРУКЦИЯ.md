## 2. Одна кнопка
1. Откройте несколько обычных вкладок Chrome/Edge либо Steam-клиент: нужны2–4 читаемых native-x64 **рендерера одного семейства**. Программа не запускает нагрузки за вас. Уже работающие Python/Node/Steam могут попасть в отдельное read-only наблюдение.
2. Закройте игры перед GPU-тестом, другие экземпляры ElasticMem и старые бенчмарки. Не выбирайте античит/защищённые процессы. Оставьте запас свободной RAM.
3. **Лаборатория**: **Расширенный Г0/Г5** включён по умолчанию. Без trim —10минут read-only наблюдения, около минуты собственной CPU-калибровки и остальные проверки.
4. Для Г0-epochs/Г5 поставьте **Г0: разрешаю trim ВСЕГО рабочего набора рендереров каждую секунду**. Изначально галочка снята! Вмешательство может вызывать задержки; cap ограничивает опрос, **не действие EmptyWorkingSet**. С расширенным режимом добавится не менее10минут на каждый из2–4рендереров: ориентировочно30–55минут всего, при медленном опросе дольше. Если нельзя мешать браузеру — галочку не ставить.
5. Нажмите **Проверить всё — автоматически**. Это согласие на локальное чтение до64МиБ памяти рендереров. Снимки могут содержать пароли/переписку; в обычный ZIP не входят. Агент остановится и после партии останется остановленным.
6. Работайте как обычно, не закрывайте выбранные процессы. По завершении откроется папка ZIP. Итоговый текст уже содержит размеры Г4, виртуальные V(T)/R(T), полезность Г5 и GPU/дисковые медианы.

Кнопка **Проверить всё (читает память)** в главном окне использует настройки Лаборатории.
Для короткой проверки снимите расширенный режим:120с наблюдения; при согласии trim —12эпох на максимум2рендерерах и bounded subset. Это проверка механики, не исследование объёма.
**Отменить** сохраняет частичные данные с неуспешным статусом. Закрытие ждёт остановки работы; GPU timeout может потребовать перезапуска. Submitted ресурсы не освобождаются преждевременно.

## 3. Автоматические этапы
- **Окружение**, затем повторный probe: read-only Get-MMAgent/RAM/ОС. Видимый working set MemCompression **не равен compressed payload**. Недоступные payload/логический объём/ratio —null, не0. Кодек конкретной Windows-сборки по общему ratio не определяется.
- **Самопроверка**: кодеки/контейнеры/mappings/models/export/bitpacked epochs; на Windows native Xpress/Huffman. При ошибке зависимые этапы skipped.
- **Г0-счётчики**: до5 уже работающих Chrome/Edge/Steam/Python/Node, по возможности разных типов. При отсутствии —observer-only. Этот широкий список **никогда не используется для trim/снимков**. PageFaultCount объединяет soft/hard faults; это не SSD-трафик или page-access trace.
- **Калибровка**: собственный child32МиБ;10paired rounds baseline/trim/trim+query по2секунды, ротация порядка. CPU/faults/operations/s; bootstrap5000resamples целых paired rounds,seed17. Интервал описательный: зависимость/дрейф не исчезают.
- **Own post-trim reads**: до256касания с timing/counters. Предварительная Valid может измениться. Backing origin **unknown: standby/compressed/pagefile**; это не latency Xpress/pagefile. Отдельный fault-origin этап skipped с причиной, без искусственного memory pressure.
- **Г1**: свежие2–4рендерера, до16МиБ/PID. Residency/mapping/lifetime guards до/после чтения; invalid/image/mapped/shareable исключены. Brotli-only/raw dedup/закрытый ordinal-normalization контроль; снимок не атомарен.
- **Г4**: plain Xpress, Huffman, LZ4, zstd-1 4К, zstd+dictionary4К, zstd16К. Train на первом PID, test на других; counted dictionary,24Bbindings,16Bheaders,8Bpadding,256Ballocation,8%reserve. Fresh decoder из сериализованного словаря проверяет PID/address/байты. Ratio —модель хранилища, не RSS. Gate25% —относительно plain Xpress; Huffman дополнительный ориентир. Stored restore второй/прогретый decode, не full paging;16К восстанавливаются целиком.
- **Г0-epochs/Г5**: только с отдельным согласием; методика ниже.
- **Диск QD1**: независимо от GPU; собственный новый TEMP-файл32МиБ, random aligned unbuffered reads4/64/256КиБ,100измерений после10warmups, stale-generation/wrong-offset negatives. Delete-on-close, существующие файлы не меняются. Bus/media **не подтверждены как NVMe**; cache накопителя остаётся. Seek и сравнение вне timing. Это не реальная pagefile-fault latency.
- **Г3**: software/UMA исключены. DEFAULT→READBACK copy queue4/64/256КиБ, restore/roundtrip/p50/p95/p99,6negative checks. GPU_UPLOAD/ReBAR для DMA не нужны. Пул32МиБ≤25%доступного WDDM budget; residency/durability не гарантированы.40мкс —исторический screening, не измеренная NVMe-планка. Старый GPU_UPLOAD путь отдельный.
- **Г2**: собственные fixed-schema records, не CPython/V8 patch.
- **UI**: механический bounds audit двух тем при текущем DPI; ноль warnings не визуальная приёмка.
- **Экспорт**: source-run hashes проверяются до ZIP; exported bytes получают отдельные SHA256.

Exact trace/Belady skipped. Synthetic churn в auto skipped до независимого решения по объёму; доступен вручную как контроль. Kernel pager не включается.

## 4. Расширенный Г0 и Г5
Г0: первичный VirtualQueryEx census committed/readable MEM_PRIVATE, включая нерезидентные **адреса без чтения их содержимого**. До262144опрашиваемых страниц/PID(1ГиБ виртуального диапазона); при cap address-prefix, не random. Scan stop/cap/coverage отражаются отдельно. MEM_IMAGE/MAPPED/guard/noaccess исключены.
На каждом renderer: baseline4 →trim4 →trim+residency600эпох; nominal1с, модель использует измеренные длительности. Перед каждым trim подтверждаются handle-bound image/native-x64/renderer/session/lifetime. Командная строка не сохраняется. Новые mappings после census не добавляются; одинаковый AllocationBase не доказывает отсутствие reuse.
Модель Г0 сохраняет только all-known последовательности; excluded/retained coverage выводится. Это survivorship-biased residency proxy, не exact touches/unique frames/desktop ceiling. V(T) —виртуальные байты модели; R(T) —наблюдаемые reacquisitions. Стоимости10/20/40/100мкс —сценарии, не измеренные fault costs. Нельзя объявлять V экономией сверх standby/compressed store.
Расход истории ограничен: если оценка превысит половину свободной RAM либо свободная RAM упадёт ниже512МиБ, остановка с причиной вместо pressure. Pagefile/MemoryCompression/PageCombining не меняются.

Г5: локальные private `.eet` содержат PID/lifetime/addresses/activity и known bitmap каждой эпохи. Cohort —train-known пересечение с предшествующим снимком,≤4096страниц/PID, **не фильтр по будущему test**.
Три замороженные группы до4страниц: address adjacency; train coaccess(до64spreadepochs внутри первой половины,Hamming greedy); static content histogram(dominant byte/zero/FF,не semantic model).
Кодек zstd-1/16К одинаковый. Сериализованные bindings/bytes проверяются fresh decoder; counted metadata/alignment/reserve. Ratio одного предшествующего снимка, не churn.
Test —вторая половина. Полезность = distinct pages, наблюдённые в trigger epoch и следующей эпохе(N=1). В этом окне повторный decode не начисляется. Декодируется весь блок; decoded/useful counts/fraction выводятся. Нет cache-capacity модели.
Unknown test windows исключаются с coverage, не превращаются в inactive; при любом unknown suffix continuation gate=null. Положительный gate требует mean coaccess≥2 **и** >adjacency на полностью известных данных. Недостаток событий —нет вывода, не победа. Residency reacquisition не доказывает реальные co-access/page misses.
Критерий ≥1ГиБ сверх штатных механизмов при10мс/с/процесс —решение исследования, **не вывод этого proxy** без counterfactual standby/store.

## 5. Ручные режимы
Выберите режим→параметры→**Запустить проверку**.
- **Г0-epochs/Г4**: source folder успешного локального Г1 со snapshots.
- **Г5**: source folder успешного Г0-epochs0.17+ с inputs/epochs-*.eet и copied pages/inventory. Hashes, PID/lifetime/offsets проверяются. Logs-only ZIP недостаточен.
- **Г4 churn**: собственные64страницы/256seeded alloc/free/write,blocks4/16К; живые bytes проверяются после каждого изменения, dead logical slots/payload rewrites считаются. Не real renderer churn/physical RSS/paging latency.
- **Диск QD1**: выбрать папку нужного диска; сравнение file I/O с GPU, но не доказательство NVMe/pagefile attribution.
- **Г0 exact model**: внешний exact/synthetic CSV map/read/write/unmap+metadata. Counters/DAMON/page_idle/EET не relabel exact.
- **UI screenshots**: отдельная кнопка сохраняет локальные снимки; включение в sensitive export —только осознанно.
Старый **Агент сжатия** изменяет WS через Windows; уменьшение WS не равно RAM savings. Не совмещать с исследованиями; active window/игры по умолчанию исключены. Прочие старые бенчмарки не новый kernel compressor.

## 6. Где ZIP и что прислать
После auto откроется `%LOCALAPPDATA%\ElasticMem\research-batches\<партия>\`. Пришлите **ElasticMem-logs-*.zip**, не всю runs/.
Обычный ZIP исключает snapshots/addresses/bitmaps/dictionaries/`.ecb/.eet/.emd/.erb`/screenshots. Включает агрегаты, timing CSV, manifests, auto-report. Просмотрите перед отправкой: PID/process/hardware/error могут быть личными. Экспорт не гарантированно анонимен.
На test1 разработчик автоматически публикует **только релиз приложения**. Приложение не отправляет ваши ZIP/страницы/трассы в MCP/на сервер.
`completed_with_skips` требует просмотра причин. `unsupported` —нет измерения, не отрицательная скорость. `failed/invalid/cancelled` —не результат. SHA256 доказывает целостность, не методику/самодостаточное воспроизведение без private inputs. Частичный ZIP при export failure не принимать за успешный.

## 7. CLI
CLI не делает визуальную приёмку:
```text
ElasticMem.exe --research auto --allow-memory-read --extended --out "%TEMP%\ElasticMem-auto.txt"
ElasticMem.exe --research auto --allow-memory-read --allow-working-set-trim --extended --out "%TEMP%\ElasticMem-long.txt"
ElasticMem.exe --research auto --allow-memory-read --seconds 120 --out "%TEMP%\ElasticMem-short.txt"
ElasticMem.exe --research g0-epochs --allow-working-set-trim --extended --epochs 600 --g1-folder "C:\path\successful_G1" --out "%TEMP%\ElasticMem-epochs.txt"
ElasticMem.exe --research g5 --source-folder "C:\path\successful_G0_epochs" --out "%TEMP%\ElasticMem-g5.txt"
ElasticMem.exe --research disk-qd1 --scratch "D:\scratch" --iterations 100 --out "%TEMP%\ElasticMem-disk.txt"
ElasticMem.exe --research g3-dma --adapter 0 --iterations 100 --pool 32 --out "%TEMP%\ElasticMem-dma.txt"
ElasticMem.exe --research g0-calibration --out "%TEMP%\ElasticMem-calibration.txt"
ElasticMem.exe --research g4-churn --out "%TEMP%\ElasticMem-churn.txt"
ElasticMem.exe --research verify --folder "C:\path\run"
```
`--extended` не разрешает trim; нужен отдельный `--allow-working-set-trim`. Child останавливается по конкретному Process handle, чужие процессы не убиваются.

## 8. Пока не реализовано
Подтверждённая compression/standby/pagefile attribution и их latency; стабильный build-independent payload/logical-store API; counterfactual incremental savings; exact accesses/Belady/desktop ceiling; heterogeneous foreign trim; реальный renderer churn; kernel StorPort/pagefile driver; VRAM TDR/sleep durability/migration; CPU ReBAR/AVX path; semantic pointers; CPython/V8 patch; установленная новизна Г5.
Ничего из этого не подменяется QD1, WS, synthetic fixture или static ratio.
История: hotfix0.16.1 workspace Huffman прошёл native fixtures на пользовательском Windows-прогоне. В пользовательском0.17.0 native fixtures и DMA256К выполнены, но Г0 завершился отказом QueryWorkingSetEx, Г5 не выполнен. Исправление0.17.1 требует нового Windows-прогона.
## Исправление0.17.1
В пользовательском0.17.0 Г0 остановился на QueryWorkingSetEx с Win32 error5. Причина(живой handle/выход процесса/отказ API/размер batch) из старого лога не установлена. Теперь automatic запускает каждый renderer в отдельном sealed run; отказ одного PID остаётся failed в общей партии, но не отменяет попытки других PID. Г5 берёт только успешный завершённый источник с полным запланированным числом эпох, roster и identity/offset checks; сокращённая аварией трасса не получает новый split. Counters пишутся/flush по эпохам и сохраняются при ошибке; failure log содержит PID/phase/pre-or-post/batch/code/handle lifetime без адресов. Batch1024pages соответствует размеру прежнего G1, это проверяемое ограничение, не доказанное устранение Windows-отказа. Нет повышения привилегий/обхода защиты/retries denied PID. Для диагностики одного PID CLI: --research g0-epochs --epoch-pid <PID> вместе с источником/consent;0 означает прежний all-source manual режим. Новое поведение требует Windows rerun.
